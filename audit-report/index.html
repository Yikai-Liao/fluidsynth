怎么审计

先找盲区，再证实问题。

圈复杂度用来找分支多的代码；覆盖率用来找现有测试没走到的分支。两者只是线索。两轮复审确认 51 项成立缺陷（含新增 F52），并单独保留 F26 的基线归因撤回记录；历史覆盖率、fuzz 和 Mull 未对本轮补丁重测。

  • 对 upstream/master c7ba7b49 做审计；与 24 个未合并的 fix 分支比对，排除已在那些分支处理的问题。
  • 用 Lizard 计算复杂度、gcovr 生成覆盖率；源码覆盖为 61.5% 行、45.4% 分支、67.6% 函数。高复杂、低覆盖函数优先检查。
  • 用 ASan、UBSan、LSan 做定点重现；libFuzzer 跑 MIDI、DLS、SF2 解析器，累计分别执行 428,395、471,995、195,433 次。另以有效 MTS、GS、XG 种子测试 SysEx 入口 181 秒，产生 17,525,710 个字节输入（每个输入各跑普通与试运行两条路径），没有发现崩溃。最近一轮解析器 fuzz 分别执行 91,203、131,129、65,361 次，没有发现崩溃。用 Mull 做源码级变异测试。公开合成器 API 状态 fuzz 此前跑过 164,418 个输入；之后在 F44 的精简回归序列之外，修复版又跑了 26,963,447 个输入，没有发现新崩溃。此前 11,175 与 21,483 个输入各重现并修复一个数值边界问题。
  • 原审计测试：常规 74/74；覆盖率构建 71/71；ASan / UBSan / LSan 排除两个已披露泄漏用例后 72/72。这些是历史结果，本轮测试配置和结果单独列出。
  • Mull 变异测试按源码文件筛选，得分反映本次选定回归测试能杀死的变异：MIDI parser 57%，MIDI router 87%（13/106 个变异存活），DLS parser 78%（本轮杀死 210/269 个变异），synth 31%，voice 55%（test_sfont_keynum_bounds：50/90），sequencer 50%（4/8 个存活，均为未覆盖的清理路径空值判断），单音连奏 50%（6/12 个存活）。F51 的 PTBL 分配回归是在原 DLS 变异运行之后加入；单独对该测试运行时，DLS 源文件范围内 92 个变异杀死 30 个（32%）。它仍不是 F51 的单项分数；DLS 解析器 78% 分数来自覆盖更广的另一组测试。幸存变异仍需后续测试补强。

严重度分数是本次审计的 1–10 排序分，不是 CVSS。常规合法输入和核心播放影响会提高分数；评级同时考虑实际后果、可达入口与触发条件；文件不合规不自动降低内存安全问题的优先级。每条发现时间均为新加坡时间，带“约”的为分钟级近似记录。

“修复行数”统计对应生产代码差异，不把共用回归测试代码算进源代码改动量。多个问题共用同一测试文件时，右侧列出实际测试目标。未标 ✦ 的原始行数保留初次审计口径；复审扩展项描述最终修改范围。
